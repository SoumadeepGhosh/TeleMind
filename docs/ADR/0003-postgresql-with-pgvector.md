# ADR 0003: Use PostgreSQL with pgvector for Vector Search

- **Status**: Accepted
- **Date**: 2026-11-13
- **Deciders**: Senior Staff Software Engineer, Solution Architect

---

## Context

A key capability of TeleMind is Retrieval-Augmented Generation (RAG), which requires storing and querying high-dimensional embedding vectors alongside relational metadata (users, chats, documents, permissions). Adopting a dedicated vector database (such as Pinecone, Qdrant, or Weaviate) introduces dual-database write consistency challenges, dual backups, higher hosting costs, and increased operational complexity.

## Decision

We will standardize on **PostgreSQL 16** with the official **`pgvector`** extension:

- Use `vector(768)` data type to store embeddings generated by Gemini `text-embedding-004`.
- Use HNSW indexes (`vector_cosine_ops`) for fast similarity search.
- Leverage Prisma ORM for relational schemas, complemented by raw SQL queries for vector similarity calculations.

## Consequences

### Positive

- Single database engine for both relational and vector data.
- Full ACID transaction guarantees across documents, chunks, and embeddings.
- Simplified operational model: standard PostgreSQL backups, monitoring, and scaling.
- Eliminates SaaS vector database fees and network latency.

### Negative / Trade-offs

- Scaling past tens of millions of high-dimensional vectors may require specialized partitioning or memory tuning.
